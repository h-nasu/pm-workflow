Use this skill when you need to write tests for existing or new functionality.

## Steps

1. **Analyze**: Review the specification and design documents to understand what should be tested
2. **Identify Gaps**: Determine which behaviors lack test coverage
3. **Define Test Strategy**: Choose the appropriate test types (unit, integration, e2e) following `rules/testing.md`
4. **Write Test Cases**: Create tests with clear inputs, expected outputs, and edge cases
5. **Run Tests**: Execute all tests and verify they pass
6. **Review Coverage**: Check that critical paths and edge cases are covered
7. **Document**: Record test results in `06-tests/` under the document structure

## Standards

- Follow the coding standards in `rules/coding.md`
